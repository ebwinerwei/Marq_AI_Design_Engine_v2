## 复现和试用

在仓库根目录运行。最后一条命令解压经过哈希核验的原包，自建两个临时数据库，以本机回环 HTTP 经过保存、审批、导出、恢复和重新打开全过程。

```sh
python3.12 -m unittest discover -s tests -v
node tests/project-forms.mjs
node tests/pilot-views.mjs
python3.12 tests/baseline.py
python3.12 tests/acceptance/history.py ../Marq_MADE_Engineering_3_1_1.zip
```

以下命令以空白临时目录启动试点。按 Ctrl-C 结束服务。可保留该目录供复查。

```sh
pilot_data=$(mktemp -d)
python3.12 server.py --port 18081 --data "$pilot_data" --open
```

1. 在「ルールと設計条件」勾选「この案件で意図計画を使う」。选择目标面后保存基准版。
2. 在立面页选「入口付近に余白」或「二つのピークをつくる」，点击「意図案を作成」。可输入百分比或拖动峰位、余白边界。已保存的入口或标志使用该修订内的引用。缺入口时界面提示中央为暂定位置。
3. H/V 指定方案保留原配列。独立的 wave 立面在设计者确认别册适用范围后开放番手选择。试点实现每面最多 96 格，整数搜索预算为 25,000 个节点。这是实现边界，品牌规定和客户设备性能门槛另行签认。
4. 在立面看目标曲线、实际面积、余白及变更板。保存派生版，在「比較・出力」选择该修订导出。Excel 的「意図案比較」记录比较源、数量分母、判断状态、事实 ID 和变更板号。影像、几何、数量及说明依赖分别记录。改窗或板型后需重新确认意图。
5. 使用已有 Chrome 和可解析的 Playwright 时，可对临时测试服务运行 `node tests/acceptance/pilot.cjs 18081`。该脚本创建合成案件。用 `node tests/acceptance/orbit.cjs 18081 /tmp/marq-orbit-output` 记录释放版或试点的相同 24 帧。这两个脚本仅用于验收。

## 通道、回退及待验事项

试点的本地流程可离线运行。外部通道需在配置中心已有账号和端点上补齐 `verifiedChannels.text` 或 `verifiedChannels.image`。每个记录包括 `account`、`endpoint`、`model`、`contract`、`region`、`retention`、`sampleTest`、`expires`。这些字段由实际合同及合成样本测试结果填写。设计者通过「外部接続の許諾」选用已核验通道，勾选外部发送并保存。照片另在「写真の使用許諾」记录底图和前景许可。撤销或到期后，试点网关拒绝请求。配置文件和凭据保存在服务端私有数据目录。

发布采用版本目录和独立数据目录。演练次序为原包生成批准版、备份、新分支恢复至空目录、比对历史产物、试点保存新修订、再次备份并恢复。回退时停掉试点，重新指向原程序和切换前数据目录。试点期间的新修订和产物保留在试点备份中。单个项目也可以打开基准修订查看，或解除意图后保存新的工作草案。意图选解的 JSON 交接保存项目、修订和结果 ID，导入时从有权限的源修订建立副本。跨环境交接使用完整备份。
